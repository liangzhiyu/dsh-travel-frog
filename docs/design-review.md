# 蛙旅：玩法选择与对抗评审

## 调研依据

- [Hit-Point 官方 FAQ](https://hit-point.co.jp/games/tabikaeru/faq/faq.html)：行囊影响路线，离家等待后带回照片或特产。借鉴「有限准备—等待—惊喜收藏」循环。
- [DeepSeek Harness 官方介绍](https://www.deepseek.com/harness/en/)与[源码](https://github.com/deepseek-ai/deepseek-harness)：界面和模型能力可通过插件扩展。本项目针对实际安装的 0.2.1-rc.2 SDK 实现。

素材、地点、文案和 SVG 均为本项目原创，不使用《旅行青蛙》的角色图片、音频或原作文案，与原作及 DeepSeek 官方无隶属关系。

## 三条路线

| 方案 | 价值 | 反方意见 | 决定 |
| --- | --- | --- | --- |
| 闲庭旅行 | 低打扰，离线可玩，收藏有目标 | 单纯倒计时很快无聊 | MVP：三种行囊分别对应两处地点，优先未到访地点 |
| 专注远足 | 与工作时间结合 | 容易变成工作监控、养宠压力 | 暂不做，不奖励 token 或工具调用量 |
| 灵感采风 | 用户主题带来个性化 | 静默费用、失败、隐私风险 | 显式点击模型写信，无后台生成，无聊天读取 |

## 三个子代理的对抗意见及落实

1. 玩法评审：第一次等待不可太久、每次必须有收获。落实一分钟体验、每次一张完整本地明信片和地点纪念物，无付费抽卡、无签到惩罚。
2. 平台评审：不能拿独立网页冒充 DSH 插件。使用原生 main/sidebar.panellist 插槽、实际宿主安装及浏览器验证；兼容性限定验证版本。
3. 独立反方：多标签 storage 事件不具备原子性。所有本地读改写使用 Web Locks；生成另有跨标签锁及服务端单并发/缓存；无锁环境拒绝写入并提示。

时间由本地时钟计算，不防作弊，不做交易或排行榜。出发时确定结果；归来按固定旅程 ID 结算。关闭应用不执行后台任务，再打开面板才结算。收藏保留最近200张；被淘汰卡片对应的地点若无其他卡片，将重新显示未收藏。

## 首版边界

不提供云同步、系统通知、无限自动旅行、项目内容采集、任务成果判定、用户账户系统。DeepSeek 叙事只发送插件内明确填写的主题与虚构游戏事实。模型不决定奖励，也不能调用工具。模板一直可用。
